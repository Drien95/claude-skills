# Journal de mesure

But : prouver (ou non) que la méthode réduit les itérations. Référence avant méthode : épée K3L ~90 versions, trône ~dizaines.

Fichier : `journal/mesures.md` à la racine du repo de skills (une ligne par pièce, tous builds confondus). Le compléter :
- **à l'ouverture** d'une pièce : build, pièce, date de début, budget ;
- **à chaque planche de décision** : +1 dans « Planches » ;
- **à la clôture** : date de fin, heures (temps de travail réel, estimé depuis le fil), versions totales, posés final, note finale, et une cause si > 3 planches ou > 10 versions.

Objectif : ≤ 10 versions et ≤ 3 planches par pièce, note ≥ 7,5, budget tenu.

La mise à jour du journal passe par le même chemin que les leçons : branche + PR (voir `capitaliser.md`), ou un commit groupé en fin de pièce.
